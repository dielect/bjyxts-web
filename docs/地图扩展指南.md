# 地图与 NPC 扩展指南（用原版素材）

本文记录原版地图、NPC 和传送点的数据结构，以及在网页版里新增地图和人物的方法。所有结论都对照 `game-src/Data` 和 `game-src/scripts` 核实过（2026-10-04）。

> 状态说明：第 1～3 节是已核实的原版结构。第 4.1 节的扩展层（`src/game/web_mods.rb`）已完成并通过测试（2026-10-04），支持新地图、能交谈 / 查看 / 战斗的 NPC、传送点、改地形和带条件分支的事件。

## 3. NPC 与传送点的结构

### 3.1 NPC 就是地图事件

以地图 3 平安镇西的“道德和尚”（事件 4，坐标 9,9）为例：

| 字段 | 值 | 含义 |
|---|---|---|
| 事件名 | `道德和尚` | **直接作为 NPC 名字显示**（`005 - NPC_Name.rb` 的 `Draw_event_name` 读取事件名） |
| `graphic.tile_id` | 838 | 外观是图块集里的一格人物头像，而不是行走图 |
| `trigger` | 0 | 按确定键触发 |

事件指令按固定模板组织：

```
355 @s=Draw_event_name.new            # 显示名字标签
102 [交谈, 查看, 战斗], 取消=5        # 选项，取消键进入 403 分支
  402 交谈 → 条件分歧 + 101 对话文字
  402 查看 → 355 $scene=Lookover.new("道德和尚","5",$levels[0],$attacks[1],"布衣","慈眉善目的得道高僧……")
  402 战斗 → 设置 $trea1..$trea4（掉落物）→ 301 敌群 30 → 胜利分支里改道德（变量 160）、
             记录死亡（$live[30]=false、开关）等
  403（取消）
404
355 @s.dispose                        # 清除名字标签
```

名字为“恶人”的事件是特例：会显示随机生成的恶人姓名，战斗数据取 `get_npc_data(125)`（捕快任务使用）。

### 3.2 能战斗的 NPC 需要三处数据

1. **地图事件**：上面的模板，“战斗”选项里调用敌群。
2. **敌人和敌群**：`Data/Enemies.rxdata`、`Data/Troops.rxdata`（原版共 143 个敌人）。
3. **NPC 数值表**：`013 - Data_NPC.rb` 的 `get_npc_data(敌人编号)`，按敌人编号存一行：

   ```
   [膂力, 敏捷, 悟性, 根骨, 拳脚, 兵刃, 轻功, 内功, 招架, 武器编号, ?, ?,
    [武功, 等级] × 12, ?, ?, 经验, ...]
   ```

   战斗开始时 `100 - Scene_Battle 1.rb` 第 34 行用 `$game_troop.enemies[0].id` 查这张表。

### 3.3 传送点

- 无名事件（`EV001` 这类），`tile_id` 为 0，`trigger` 为 1（主角踩上去时触发）。
- 指令只有两条：`250` 播放音效 `Move`，然后 `201 [0, 目标地图, x, y, 朝向, 0]`。
- 没有外观的事件不挡路，所以传送点放在可行走的格子上即可。

### 3.4 读档时会清空的数据（设计剧情时必须避开）

`004 - Methods.rb` 第 145～160 行，读档时会：
- 清零变量 1～10、98；
- 关闭开关 10～18、49～94、98；
- 收走身上全部石料（物品 21）；
- 清零变量 91～96（属性加成）。

**新剧情的进度请用开关 102 号以后、变量 161 号以后。**

## 4. 扩展方法

### 4.1 方式一：扩展层（推荐）

思路：在游戏读取 `Data/*.rxdata` 时动态加入新内容，原版数据文件一个字节都不改。删掉内容文件，游戏就完全回到原样。

- **接入点**：`src/ruby/rgss_kernel.rb` 的 `load_data`。
  - 读文件前调用 `WebMod.generate`：`Map052.rxdata` 这类新地图的文件不存在，由它现场生成。做法是读入模板地图（`base`）的地形、尺寸、图块集和音乐，清空事件后再放入新事件。
  - 读入原版文件后调用 `WebMod.patch`：给 `MapInfos` 追加新地图名（地图左上角显示的名字就从这里读），给已有地图追加事件、改地形。
- **引擎**：`src/game/web_mods.rb`。
- **内容**：`src/game/mods/*.rb`，构建时按文件名顺序紧接引擎载入（在 Main 之前）。以后新增剧情就往这里加文件，建议按剧情线分文件，例如 `010_打狗棒法.rb`。

#### 写法

下面的坐标都实际验证过（用地图 6 老婆婆家的地形，从北郊进出）：

```ruby
WebMod.map 52, name: '城隍庙', parent: 21, base: 6 do |m|       # 复制地图 6 的地形
  m.npc 9, 6, name: '庙祝', tile: 850,
        talk: ['施主请留步。', '本庙香火不旺，让施主见笑了。'],   # 每个字符串一页对话
        look: { age: 6, text: '一个须发皆白的老庙祝。' }
  m.npc 12, 7, name: '小沙弥', tile: 851 do |c|                  # 需要条件时用块写交谈内容
    c.if_switch(102) { c.text '你又来啦。' }.else { c.text '初次见面。'; c.switch(102) }
  end
  m.door 9, 11, to: [21, 10, 4], dir: 2                          # 出门回北郊
end
WebMod.edit 21 do |m|
  m.door 9, 3, to: [52, 9, 10], dir: 8                           # 北郊新增入口
end
```

| 方法 | 作用 |
|---|---|
| `WebMod.map 编号, name:, base:, parent:` | 新地图。`base` 是模板地图（1～51），`parent` 是父地图（只影响地图树） |
| `WebMod.edit 编号` | 修改原版地图 1～51。同一张地图可以在多个文件里 edit |
| `m.npc x, y, name:, tile:, talk:, look:` | NPC，按 3.1 的原版模板生成：名牌 → 交谈 / 查看 → 取消。`tile` 是头像 824～887。`look` 可以是字符串，也可以是 `{ age:, level:, attack:, items:, text: }`（`text` 自动按 20 字一行拆开，最多 100 字，标点不放行首）：`age` 是年龄的十位数（6 → “60多岁”），`level`、`attack` 是 `$levels`、`$attacks` 的下标 |
| `m.door x, y, to: [地图, x, y], dir:` | 传送点，主角踩上去时触发。`dir`：0 保持 2 下 4 左 6 右 8 上 |
| `m.tile x, y, 层, 图块编号` | 改地形，图块编号见 `docs/图块总览.png` |
| `m.event x, y, name:, tile:, trigger: do \|c\| ... end` | 通用事件，用指令构建器写内容 |

指令构建器（`npc` 和 `event` 的块参数）：`text`（一页对话）、`script`（脚本，可多行）、`switch`、`variable`、`se`、`transfer`、`wait`、`choices`、`if_switch` / `if_variable` / `if_script`（可以接 `.else { }`），以及直接写原版指令的 `cmd(代码, 参数...)`。缩进和分支结束标记由构建器自动处理。

#### 编号规则

- 新地图从 52 开始。
- 新地图里的事件从 1 开始编号；追加到原版地图的事件从 1001 开始。自开关按“地图 + 事件编号”存，这样不会和原版事件共用自开关。
- 剧情开关用 102 号以后，变量用 161～200（见 `docs/内容设计思路.md` 的分配表）。
- 存档不受影响：读档时原版会把主角送回地图 4 并重新读取地图数据，不会用到存档里旧的地图内容。

#### 工具和测试

> 放事件一定要用 `node tools/mod-maps-test.mjs` 检查“事件可到达”：它从地图的每个入口按真实通行规则走（不踩出口），每个新加的事件都要走得到。用传送测试是发现不了的——绿玉竹杖、珍珑棋局都曾放在看着能走、实际只能穿过出口才进得去的地方。

- `node tools/mapview.mjs 21`：打印地图的通行表（`.` 可走、`X` 不可走，事件用字母标出）和事件明细，包括传送点的目标。`--raw` 查看原版，`list` 列出全部地图。用它确定 NPC 和传送点的坐标。
- `node tools/mod-maps-test.mjs`：回归测试。检查没声明修改的原版地图载入后与原版完全一致；修改过的地图原有事件不变、地形只在 `tile` 声明处变化；传送点目标存在、落点和传送点本身都能走、通往新地图的门有回程；同一格不放两个事件。另用内置示例检查引擎生成的 NPC 指令与原版模板一致。
- `node tools/encounter-test.mjs`：江湖奇遇的抽取规则、计步、奖励校验值、掉落和事件脚本语法，以及装备特效。
- 两个工具读的都是构建产物，改完内容先运行 `python3 tools/build.py --fast`。
- 坐标越界、父地图不存在、编号不合规等错误，在游戏读取数据时直接报错，不会悄悄出错。

#### 自制 NPC 外观

原版 NPC 在地图上用的是图块集里的 32×32 头像。新 NPC 可以换成自己画的外观：

1. 准备 32×32 的素材：黑色和墨绿 #90B057 两色，角色以外透明（例如 `assets/npcs/32x32/old-beggar.png`）。
2. 运行 `python3 tools/make_npc_sprite.py 素材.png 图片名`（需要 Pillow），生成
   `game-src/Graphics/Characters/图片名.png`（行走图，同一帧铺成 4×4）和 `game-src/Graphics/Battlers/图片名.png`（战斗图）。
3. 地图上用 `m.npc ..., sprite: '图片名'`；能战斗的再在 `WebMod.enemy` 里加 `battler: '图片名'`。
   石桌之类的物件同样适用：加 `--no-battler` 不生成战斗图，地图上用 `m.event ..., sprite: '图片名'`。

调查时显示近景图：图片放进 `game-src/Graphics/Pictures/`，事件里用 `c.show_picture 编号, '文件名'`（默认以 (320, 168) 为中心，正好在对话框上方，288×288 左右合适），用完 `c.erase_picture 编号`。例子见 `030_小无相功.rb` 的珍珑棋局。

不需要改原版图块集和通行数据；测试会检查用到的行走图文件都存在。

#### 给原版 NPC 换台词

原版 140 个能交谈的 NPC 里，有 96 个的“交谈”只是调用“一般交谈”（公共事件 3），随机说“今天的天气真是，哈哈”之类的五句之一。用 `m.talk` 换成自己的台词：

```ruby
WebMod.edit 12 do |m|
  m.talk '流氓' do |c|                       # NPC 名字（地图上唯一），也可以写事件编号
    c.if_dead(122) do                        # 流氓头（敌人 122）已被杀
      c.text '老大……老大被人打死了，我、我以后跟谁混啊……'
    end.else do
      c.one_of '老大说了，见着穿得好的就上去要钱。',  # 每次随机说一句
               '商业街路边那个老叫化，我们去抢过一回，结果……不说了。'
    end
  end
end
```

- 默认只替换“一般交谈”那一条指令，NPC 原有的任务判断（平一指任务、石料任务等）全部保留。
- 本来就有自己台词的 NPC，要加 `override: true` 才能替换；它会换掉交谈分支里的内容，只保留外层的平一指任务判断，所以只用于台词固定、没有任务的 NPC。不加时会报错提醒。
- 指令构建器里常用的写法：`c.text`（一页）、`c.one_of(...)`（随机说一句）、`c.random(n) { |i| ... }`（随机分支）、`c.if_good`（道德 ≥ 128）、`c.if_dead(敌人编号)`、`c.if_switch`、`c.if_variable`、`c.if_script`。
- `npc ..., talk: [...]` 是一次交谈里按顺序说完的几页；想每次随机说一句，用块加 `c.one_of`。
- 随机数暂存在变量 9（原版“一般交谈”也这样用，读档时清零）。
- 示例见 `src/game/mods/020_平安镇对话.rb`（平安镇一带 13 个 NPC）。
- 测试会检查：用 `talk` 改过的 NPC，除交谈分支外和原版完全一样。

#### 能战斗的 NPC

分两步：先用 `WebMod.enemy` 定义数据，再在地图上用 `npc ... fight:` 摆放。

```ruby
WebMod.enemy 144, name: '城隍庙武师', tile: 852, like: 30,          # 以道德和尚为模板
             maxhp: 300, gold: 50,
             stats: { 膂力: 30, 闪避: 20, 拳脚: 58, 经验: 50000 },
             skills: { 40 => 80, 58 => 60, 47 => 50 }                # 基本拳脚 80、太极拳 60、基本招架 50

WebMod.map 52, name: '城隍庙', parent: 21, base: 6 do |m|
  m.npc 11, 8, fight: { enemy: 144, loot: [[:armor, 4], [:item, 16, 2]],
                        morality: [-10, -5], switch: 103 },
        talk: ['来比划比划？'], look: '一个精壮的武师。'
  # ……
end
```

`WebMod.enemy 编号, name:, tile:, like:, ...`

| 参数 | 说明 |
|---|---|
| 编号 | 从 144 开始，连续编号。敌群用同一个编号（原版惯例） |
| `like` | 模板 NPC 的敌人编号，复制它的敌人、敌群和数值表后再改。不能用 125（随机恶人）、129～135（舞林大会）、143，以及敌群对不上的 37、38、41、90 |
| `tile` | 头像 824～887。战斗画面自动用 `NPC_Tile_(tile − 823)`，与原版 134 个 NPC 的规律一致 |
| `maxhp`、`maxsp`、`gold` | 气血、内力上限、战胜得到的金钱 |
| `stats` | 数值表字段：膂力、敏捷、悟性、根骨；拳脚、兵刃、轻功、内功、招架（**当前启用的武功编号**）；武器、装备1、装备2；命中、闪避、经验、门派、防御、附加膂力、附加敏捷 |
| `skills` | `{ 武功编号 => 等级 }`，最多 12 门，给出时整体替换模板的武功 |
| `elite` | `true` 时不会被流星飞掷击中（原版 126 号以后的强敌都是这样）。默认 `false` |

`npc ... fight:` 可以只写敌人编号，也可以写成哈希：

| 键 | 说明 |
|---|---|
| `enemy` | 敌人编号。`npc` 的 `name`、`tile` 不写时取敌人定义里的 |
| `loot` | 战利品，最多 4 种：`[:armor, 4]`、`[:weapon, 15]`、`[:item, 16, 2]`（第三项是数量）。原版 NPC 大多掉落 `[:armor, 4]` 布衣 |
| `morality` | 杀死后道德值（变量 160）的变化：`[道德 ≥ 128 时, 道德 < 128 时]`。原版好人多为 `[-10, -5]`，坏人如流氓头是 `[4, 0]`。不写则不变 |
| `switch` | 杀死后打开的开关，剧情里判断“这个人死了”用。从 102 号以后选 |
| `lose` | 战败：`:death`（默认，公共事件 25：道德低于 128 则死，否则“承让了。”）或一句台词，例如 `'承让了！'`（切磋） |
| `corpse` | 死后显示的图块，默认 508（骷髅） |

生成的战斗分支与原版 NPC 相同：战胜后游戏会问“这一刀是劈还是不劈呢？”，选“确定”才算杀死。杀死时改道德、打开 `switch`、记 `$live[编号] = false`、事件换成尸体页；不论杀不杀都给战利品和金钱。

数值怎么起作用：攻击是否命中由攻击方膂力对防守方**敏捷**、加上双方经验差决定（`025 - Game_Battler 3.rb` 的 `attack_effect`）。`stats` 里的“闪避”会加进 NPC 的敏捷，“经验”参与经验差计算。所以想让 NPC 难打中，调“闪避”或“敏捷”即可，不需要改战斗公式。

注意：

- 新 NPC 的编号在 144 以后，原版任务（只在 5～124 中挑目标）和结局统计（只数 1～124）都不会算到它们。
- 测试会检查：敌人、敌群、数值表都生成了，战斗图存在，武器 / 防具存在，武功都在武功注册表里登记，启用的武功在它的武功列表里，每个定义的敌人都摆到了地图上。

| 写法 | 作用 |
|---|---|
| `WebMod.weapon 31, like: 25, name:, atk:, price:, description:, ...` | 新武器，复制模板后改字段。编号接着原版连续（31 起） |
| `WebMod.skill 28, like: 22, name:, sp_cost:, description:` | 新绝招，编号接着原版连续（28 起） |
| `WebSkill.weapon_type 39, [31, 32, 33]` | 登记武器类型（对应的基础武功）。没登记的武器装备后战斗会出错，测试会拦住 |
| `WebSkill.perform 84, 28` | 启用武功 84 后学会绝招 28 |
| `WebSkill.attack_words 84, [[最低等级, 描述, 威力, 命中修正, 伤害类型], ...]` | 普通攻击的招式描述。拳脚、兵刃武功都必须有，否则攻击时出错 |
| `WebSkill.skill_words 28, ['……']` | 绝招描述 |
| `WebSkill.combo 28, moves_of: 84, times: 4, stun: { state: 1, text: '……' }` | 连击型绝招：用哪门武功的招式、连击几次。`stun` 可选：至少打中一下且对方没倒下时，按原版乱环诀的内力比拼判定是否施加状态（原版“木鸡”：1 木鸡3、2 木鸡5、19 木鸡8） |
| `WebMod.item 23, like: 19, name:, description:` | 新物品，编号从 23 起。剧情道具可以用 19 三角石板为模板（不能使用、不能卖） |
| `WebSkill.requirement 28, [[30, 84], [84, 60], [39, 60]]` | 绝招使用条件：变量小于 38 的项要求“当前启用”等于该值（29 拳脚、30 兵刃、32 内功），其余项要求等级不低于该值 |
| `m.npc ..., shop: [[:weapon, 31], [:weapon, 32]]` | NPC 加“交易”选项，与原版小商贩相同 |
| `c.gain(:weapon, 33)`、`c.lose(:item, 2, 1)` | 事件里增减物品 |

描述里用 `%{user}`、`%{objector}`、`%{weapon}`、`%{sp}`（攻击部位）代替人称、兵器名和部位。

新秘籍：`WebMod.item` 建物品并把 `common_event_id` 指向 `WebMod.common_event 26, '使用-秘籍名' do |c| ... end`（编号从 26 起），公共事件里照原版判断识字和门派后执行 `$scene=Scene_Study.new(7, 编号)`；学习列表用 `WebSkill.study 7, 编号, [[武功, 最高等级]]` 登记（原版逍遥派秘籍是 1～5）。完整例子见 `src/game/mods/030_小无相功.rb`。

新武功：`WebSkill.add_skill 编号, WebSkill::INNER, 基础武功` 登记分类，`WebMod.variable_name 编号, '名字'` 起名（武功名就是同编号变量的名字）。

绝招的内力和使用条件经过三个可重定义的方法：`WebSkill.sp_cost`（显示与判断用的消耗）、`WebSkill.consume_sp`（实际扣除）、`WebSkill.requirements_for`（使用条件）。默认与原版相同；`src/game/mods/030_小无相功.rb` 是重定义它们的例子。原版条件表的原文在 `WebSkill::ORIGINAL_REQUIREMENTS`。

`node tools/skill-baseline-test.mjs` 会检查：每件武器都登记了类型，拳脚、兵刃武功都有招式描述，新绝招都有数据、描述和使用条件，连击绝招用到的招式有描述。漏了任何一项，测试直接报出是哪一项。

#### 防具、装备特效、商人添货

完整例子见 `src/game/mods/050_江湖装备.rb`。

| 写法 | 作用 |
|---|---|
| `WebMod.armor 32, like: 24, name:, kind:, pdef:, dex_plus:, price:, description:` | 新防具，编号从 32 起。`kind` 是部位：0 鞋 1 头饰 2 外衣 3 盔甲。模板带的状态加成（`auto_state_id`）、属性加成要显式清零 |
| `WebGear.effect :weapon, 34, :crit, chance: 20, ratio: 0.5, name: '秋水'` | 装备特效，每件最多两个。25 种特效的参数见 `src/game/web_gear.rb` 开头；武器、防具都能带任何一种 |
| `when: { skill: 83 }`、`{ sect: 1 }`、`{ unarmed: true }`、`{ good: 200 }`、`{ evil: 128 }`、`{ active: 70 }` | 特效的生效条件：出手用的武功、门派、空手、道德、启用了某门武功 |
| `WebGear.set :乾坤, '乾坤', pieces: [...], tiers: { 2 => [[:power, ratio: 0.1]], 4 => [...] }` | 套装：穿上几件得到对应档位（档位叠加）。`pieces` 的一项写成数组表示几件任选其一 |
| `[:level, skill: 85, n: 15]` | 武学精进：战斗中这门武功视为 +15 级（同一门最多 +20，没学的不加，存档里的等级不变） |
| `[:cost, ratio: 0.3, skills: [2, 3]]` | 绝招省力（`skills: :all` 为所有绝招），合计最多 -60% |
| `m.goods '何铁手', [[:weapon, 37]]` | 给原版商人添货（`WebMod.edit` 块里），原有商品不变 |

特效只对玩家生效。`description` 只写一句描述（一页以内）；特效、套装件数和各档效果由引擎自动生成，物品栏里左右键翻页查看，商店购买时顶栏显示描述和特效标签。批量定义装备用 `WebEquip.weapon` / `WebEquip.armor`（050 开头），一行一件。

`m.npc ..., shop: lambda { |c| c.if_variable(21, 1) { c.shop([[:armor, 41]]) }.else { c.text '……' } }`：交易分支自己写，可以按门派、等级卖不同的货（例子见 `070_门派军需官.rb`）。`node tools/gear-test.mjs` 检查装备数据、说明、套装和每种特效。

#### 江湖奇遇

完整例子见 `src/game/mods/060_江湖奇遇.rb`，引擎在 `src/game/web_encounters.rb`。

```ruby
WebEncounter.add 7, '恶霸欺人', where: %i[wild suburb town], weight: 2, cooldown: 4,
                 if: -> { WebEncounter.good? } do |c|
  c.text '一个满脸横肉的恶霸揪着卖菜老汉的衣领。'
  c.choices(%w[出手相助 视而不见]) do |i|
    ...
  end
end
```

| 参数 | 作用 |
|---|---|
| 编号 | 1～40。存档用变量 260 + 编号 记录它发生在第几次奇遇 |
| `where` | `:wild` 大地图与各处山野、`:suburb` 平安镇四郊、`:town` 镇上，可以写数组或地图编号 |
| `weight` | 权重，数字或 lambda |
| `once` / `cooldown` | 只发生一次 / 发生后至少再过几段别的奇遇才会再出现 |
| `after: [2, 3]` | 奇遇 2 发生过，并且之后又过了 3 段奇遇（“日后报恩 / 寻仇”） |
| `if:` | 额外条件。常用：`WebEncounter.good?`（道德 ≥ 128）、`.age`、`.exp`、`$game_switches[n]` |
| `show: { tile: 841 }` | 看得见的奇遇：先在主角前方路边出现这个人或物，碰到才开始；离开地图、走远就回收，没碰到的不算发生 |
| `combat: true` | 会打起来的奇遇，两段之间至少隔一段不打架的 |
| `weight: -> { ... }` | 按情境定权重：`WebEncounter.gold`、`.hp_rate`、`.wanted`、`.mountain?` |

奇遇块里能用的指令和 NPC 交谈块相同，另有几个常用的：

| 写法 | 作用 |
|---|---|
| `c.fight 145, loot: [[:armor, 32, 1, 30]], win:, killed:, spared:, lose:, escape:` | 打一场。`loot` 第 4 项是掉落几率（%）；打赢后按玩家选“劈 / 不劈”分别执行 `killed` / `spared`；打输执行 `lose`（不会像原版那样被杀） |
| `c.reward exp: 300, pot: 100, morality: -5, wanted: 1` | 加经验、潜能、道德、通缉值（变量 164），自动同步原版的校验变量。注意原版变量 159“追杀数”是杀死的恶人数，不是通缉 |
| `m.event ..., switch: [142, 146], variable: [165, 2], once: true` | 事件出现的条件：开关（最多两个）、变量达到某值；`once` 时事件里执行 `c.done` 后就消失（例子见 `100_正邪分支.rb` 的分舵） |
| `c.gold(300)`、`c.gold(-100)` | 加减银两 |
| `c.say 'WebLife.landed_text'` | 一页内容在运行时才决定的对话（表达式的结果就是要显示的文字） |
| `m.rewrite(8) { \|c\| ... }` | 重写原版机关类事件第 1 页的指令（外观、触发不变），例如南郊的钓点；NPC 台词请用 `talk` |
| `c.if_gold(500) { }`、`c.if_has(:item, 9) { }` | 条件：银两够不够、身上有没有某样东西 |

节奏：野外每走一步计 2，郊外和镇上计 1，计满 60～120 抽一次；刚发生过的两段不会紧接着重复。`node tools/encounter-test.mjs` 检查抽取规则和每段奇遇里脚本的语法。

**对话后面紧跟选项时**，对话和选项共用一个 4 行的窗口：对话按自动换行后的实际行数排在上面，选项接在下面。放不下时选项单独显示，玩家选的时候就看不到问题了。所以选项前的最后一句尽量短（3 个选项时一行以内），长的描述拆到前一页。4 个选项总是单独显示。

### 4.2 方式二：RPG Maker XP 编辑器

适合需要大量画地形的新地图（例如整个新门派）。

1. 在 Windows 上安装 RPG Maker XP，新建一个工程。
2. 用本仓库 `game-src/` 里的 `Data/` 和 `Graphics/` 覆盖工程里的同名目录。
3. 在编辑器里画地图、放事件（NPC 外观选“图块”，照抄 3.1 的指令模板）。
4. 把改好的 `Data/MapXXX.rxdata` 和 `MapInfos.rxdata` 拷回 `game-src/Data/`，运行 `python3 tools/build.py` 重新构建。

两种方式可以混用：地形用编辑器画，剧情逻辑放在扩展层里写，方便版本管理和代码审查。

### 4.3 注意事项

- 新地图编号从 52 开始，不要覆盖原版的 1～51。
- 事件里的字符串直接写 UTF-8 中文即可（运行时会统一处理原版数据的编码）。
- 消息窗口会自动换行，一条 `101` 指令就是一页对话。
- 运行时没有加载 JSON 库，调试脚本里不要使用 `to_json`。
- 原版有反作弊（公共事件 4）：金钱与校验值（变量 151）不符，或任何武功等级超过当前经验允许的上限时，会清空武功变量、覆盖存档并结束游戏。剧情里改金钱用原版的增减金钱指令，传授武功从低等级起步。
- 按确定键触发的事件，如果事件的图形是**可通行**的图块（或没有图形），只有站在它上面才能触发；想让玩家站在旁边调查，用不可通行的图块（例如 643 桌子）或自制外观（`sprite:`）。想让玩家从旁边调查，给事件一个图形；想让玩家走过去就触发，用 `trigger: 1`。
