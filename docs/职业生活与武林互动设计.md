# 职业生活与武林互动设计草案

状态：设计草案，尚未实现。整理日期：2026-10-05。

本文面向后续游戏内容设计与开发，整理职业、生活方式以及普通人与武林人士互动的扩展方向。目标是让玩家即使不拜师、不练武、不参加战斗，也能在平安镇获得收入、成长、朋友和长期归属，同时减少新增长篇剧情的工作量。以平安镇的人物、场所与共同事件连接门派、职业、装备和奇遇，让玩家的经历影响后续玩法。

建议以“平安镇集会”作为首个整合试点，先验证生活活动、武林事件和熟客关系能否连接起来，再逐步做通“钓鱼、做菜、供货、摆摊、置家”的生活路线，复用订单和熟客机制扩展其他职业。下文的职业、事件与奖励均为拟议方案，不代表当前游戏已经支持。

## 设计目标与原则

玩家既能闯荡江湖，也能在镇上过出自己的一生。生活玩法需要有独立的回报：学会一道菜、收获一位熟客、做出一件署名作品、添置一件家具，都可以成为继续玩的理由。

- 职业采用随时能学的手艺，允许兼修，不要求开局选定终身职业，也不绑定门派。
- 高级工具、配方和经营资格应有非战斗获取途径，例如手艺、订单、购买和客户关系。
- 各职业需要不同的判断：厨子考虑食材与口味，商人考虑成本与销路，棋客解决棋题。避免全部变成反复点击领取银两。
- 城镇与近郊应提供可靠的安全活动范围。生活玩家遇到江湖纠纷时，应有能够完成的非战斗处理办法。
- 第一版不引入饥饿惩罚、离线欠租、限时签到。订单由玩家主动接取，经营进度可由主动休息或经营回合推进。
- 武功可以增加处理事情的方式，但生活成就不以武功等级和战斗经验作为统一门槛。

## 职业方向与长期目标

| 方向 | 日常玩法 | 主要选择 | 长期追求 |
|---|---|---|---|
| 渔夫 | 选水域与鱼饵、钓鱼、向客栈供货 | 留鱼做菜、卖给收购商、完成预订 | 鱼谱、好钓竿、固定买家、临水小屋 |
| 厨子 | 收购食材、制作菜肴、摆摊、接宴席订单 | 成本、口味、备货量与接单能力 | 私房菜谱、食客口碑、自己的食摊 |
| 郎中 | 采药、辨认病症、配药、出诊 | 药材搭配、接诊顺序与服务对象 | 医术、药方、病人信任、自己的药铺 |
| 铁匠与裁缝等手艺人 | 修工具、补衣服、定制物件，后续扩展家具与鱼篓 | 材料、用途、工艺与交货安排 | 独门图样、署名作品、自己的作坊 |
| 行商 | 打听行情、进货、运输、沿途摆摊 | 进货成本、销路、路线与护送费用 | 商路、熟客、商会信誉、铺面 |
| 书生与棋客 | 抄书、代写家书、教书、整理游记、解残局 | 接什么委托、研究什么书与棋谱 | 藏书、棋谱、学生与棋社名望 |

这些职业可以互相支持：渔夫提供食材，厨子制作饭食，手艺人制作工具，商人供应异地物产。单人游戏中应由 NPC 保持基础供求，玩家无需把所有职业练满才能经营。

## 武林人士如何参与生活玩法

武林人士可以成为客人、熟人、合作者，也会带来需要玩家判断的麻烦。他们需要普通人的手艺，玩家可以决定帮谁、怎样帮、是否长期来往。

| 玩家身份 | 武林人士的需求 | 关系发展与生活回报 |
|---|---|---|
| 厨子 | 日常吃饭、门派宴席、远行干粮 | 成为熟客、介绍同门、带回异地食材 |
| 郎中 | 比武后的伤病、远行备药、上门诊治 | 送来药材、介绍病人、提供沿途住处 |
| 铁匠或裁缝 | 修兵器、补衣服、定制护具 | 长期使用玩家作品，带来口碑和新订单 |
| 渔夫或农人 | 客栈采购、门派供货、隐居者的日常食材 | 稳定订货、交换物产、分享当地见闻 |
| 行商 | 运送门派物资、寻找稀缺物品 | 建立交易渠道，雇请侠客护送货物 |
| 书生或棋客 | 代写家书、整理游记、对弈解局 | 受邀做客、借阅书籍、替熟人传话 |

关系奖励应贴合职业。厨子得到香料和订单，郎中得到药方和信任，手艺人得到图样与署名声望。武功秘籍可以作为少数可选的交叉内容，不能成为生活路线的主要回报。

### 一个食摊与一位剑客

一个年轻剑客初次来，只买得起最便宜的饭。后来他经常来，玩家记住了他不吃辣。他远行回来时，带来一种当地香料，玩家因此学会一道新菜。再后来，他的同门来到平安镇，也会到这个摊子吃饭。

这段关系提供收入、食材、口碑和熟悉感。玩家可以关心他何时回来，无需通过战斗推进关系，也无需让每位熟客最终传授绝世武功。

建议让 NPC 的称呼随往来变化，从“客官”变成“老师傅”“先生”，或开始点玩家的拿手菜。少量有状态的台词就能体现彼此熟悉。

### 江湖纠纷中的生活选择

| 情境 | 玩家可以采取的方式 | 可能影响 |
|---|---|---|
| 两派弟子在店里争吵 | 请他们出去、找双方熟客劝和、请官差处理 | 客户关系、店铺规矩与口碑 |
| 客人定制物件却不说明用途 | 正常接单、询问来历、拒绝 | 收入、信任及后续客户来源 |
| 落魄侠客无钱付账 | 允许赊账、帮忙搬货抵账、拒绝交易 | 是否形成长期往来，是否收回欠账 |
| 门派希望包下全部产量 | 接受包销、限定供货份额、继续做散客生意 | 稳定收入、产能安排与客户构成 |
| 有仇的双方同时求医 | 按病情先后接诊、明确诊所规矩、请人协调 | 医者口碑与个人信任 |

每个情境都应允许生活玩家完成处理。拒绝委托或不选某条关系路线，也应保留正常经营的空间。善意可以得到感谢和后续来往，不必每次都兑换成重宝；普通赊账事件也不宜动辄毁掉玩家的经营成果。

## 让生活与江湖形成整体

平安镇应成为玩家能够参与、也能慢慢改变的地方。现有老叫花、独行大侠、江湖货郎、六扇门、黑风寨、珍珑棋局，以及报恩和寻仇内容，可以作为人物与事件基础。后续新增内容优先连接这些已有关系，避免职业、装备和奇遇各自独立。

### 同一件事情的不同参与方式

建议将现有“比武招亲”扩展为镇上的一次热闹。不同身份参与同一事件，共享人物、地点和事件进展，但有各自的活动与回报。

| 玩家选择 | 参与方式 | 主要回报 |
|---|---|---|
| 练武 | 上台比试、与参赛者切磋 | 名望、装备、武学见识 |
| 做饭 | 给擂台附近供饭、承办宴席 | 收入、菜谱、熟客 |
| 行医 | 为受伤的参赛者诊治 | 医术、信任、药材 |
| 做手艺 | 修理兵器、制作礼服 | 工艺、订单、署名作品 |
| 经商 | 摆摊卖药、干粮和器具 | 销路、客户、行情 |
| 看热闹 | 认识人、听消息、观察比试 | 人际关系、新去处 |

玩家只需参与自己感兴趣的一部分，不必练齐所有职业。首批只实现其中少量入口，其他职业后续接入同一事件。这样可以复用事件背景与角色，不必为每种职业单独写一条长剧情。

### 同一个问题的不同处理办法

从现有江湖内容中挑选部分问题，提供两三种真正不同的解法，让本领、银两、关系和见闻都能发挥作用。

例如拟新增“货物被黑风寨扣下”的事件，可以从以下方案中选取合适分支：

- 武人打进去取回货物，但可能结下仇怨。
- 商人谈赎价或换货，付出成本，保住后续生意。
- 与寨中某人有交情的人托其调解，得到帮助，也留下日后回报的关系。
- 熟悉地形的人为货主指出另一条路线，减少以后运输受阻的机会；这并不自动解决已经被扣的货物。
- 不想参与的人拒绝委托，继续正常经营。

不同做法应产生不同结果：有人赚到钱，有人建立商路，有人保住朋友。避免所有选项只是消耗不同资源、领取同一份奖励。不是每个事件都必须支持所有职业，但生活路线应始终有能够完成的活动。

### 能解决具体事情的人情

把关系落实为介绍生意、代购物品、借宿、作证或陪同办事等具体帮助。首批为少数熟人提供明确的帮忙选项即可，不要求复杂的 NPC 自主行动。

一个拟议的连续经历是：玩家照料受伤剑客，剑客成为食摊熟客；玩家第一次远行进货，请熟悉路线的剑客同行；剑客介绍当地药商；之后玩家获得了可以独立使用的进货渠道。救人、经营、旅行和交易由此产生联系。

熟人应有偏好与立场，不能无限免费提供帮助。交恶后可以拒绝交易，也应考虑适当的修复关系方式。界面和对话要让玩家知道关系为何变化，避免不明原因地失去经营入口。

### 留在地图上的生活成果

优先选择现有地图上的少量位置，通过物件、人物与台词变化表现玩家的积累。例如：

- 修好一处茶摊，开始有人停留，并能打听商路消息。
- 长期给客栈供货，菜单上出现玩家的拿手菜。
- 整理一处小院，作为自己的住处。
- 为石桌添置棋具，让不同棋客前来对弈。
- 帮忙改善路边设施，让货郎增加一处停靠点。

初期不需要自由建造。小院可以提供灶台、药架、棋桌等有限布置选项，改变用途与访客。首批仅做一处可见变化，确认其能带来实际用途后再扩展。

### 物品的来历与去向

为少量装备与生活物件增加人物联系，复用已有物品内容：独行大侠带回修过的刀保养；熟客穿着玩家制作的衣服，介绍别人来下单；找到旧物后可以自用、出售、收藏或归还；一件旧钓竿被隐士认出，开启新的交谈。

这些设计的价值来自来历、去向与关系，不要求给所有装备单独写故事。具体物品归属和原有用途需要实现前核对。

生活工具也可以按用途区分，例如便于远行的鱼篓、适合大量出餐的锅、便于辨药的药匣。不同生活方式有适合自己的工具，不必统一追求同一种最高等级。

### 回应玩家经历的奇遇与消息

在随机奇遇中加入与玩家行为相关的条件或权重：长期供货更容易接到宴席邀约，爱下棋会听到棋客和旧棋谱的消息，常救人会遇到求医与道谢，经常走同一商路会逐渐认识沿途货郎。独居玩家也应有访客、自然发现和邻里小事。

保留少量跨职业的意外，不把玩家锁定在单一内容池。日常经营继续使用固定入口，奇遇负责补充变化。

消息还应允许主动寻找，例如到客栈问近况、找熟人打听、查看镇上告示。建议增加简明见闻簿，记录人物委托、已知地点与传闻来源，帮助玩家找回线索，不要求玩家为了探索记住大量对话。

## 减少剧情工作量的方法

建议统一使用“需求、交易、关系、回访”的机制。多数普通往来由规则组合，少数重要人物保留专属内容。

### 可复用的订单

一张订单描述谁需要什么、需要多少、要求什么品质、支付什么报酬。客栈收鱼、裁缝收布、郎中收药可以共用同一流程。

订单应根据玩家已解锁的材料、手艺和活动范围生成。第一版采用玩家主动承接的订单，不通过离线倒计时制造损失。具体价格、产量和结算规则留待实现时验证。

### 有记忆的熟客

每位 NPC 可以配置偏好、常见需求、付款习惯、所属势力以及关系提升后的回访行为。系统记录完成交易、满意次数、欠账和关键选择，按条件触发后续往来。

个人信任、店铺口碑、门派合作可以表达不同关系，但首批不必全部做成独立数值。先让熟客识别玩家、重复消费和带来新订单，再决定是否需要更复杂的关系系统。

### 生活小事与奇遇

缺货、鱼群换了地方、客栈筹办宴席等短事件，可以改变当天适合做的事情。以简短提示和选项提供变化，减少反复阅读长对话的负担。

主动经营应是稳定可重复的主流程。奇遇只补充惊喜与后续关系，不能让玩家为了接一笔普通生意而在地图上反复走路抽事件。不同职业、地点和熟客可以复用事件结构，但应限制重复频率，并让选项产生实际区别。

## 与现有系统的衔接

当前代码中的江湖奇遇支持地点、条件、权重、冷却与前置事件，可用于生活插曲及熟客回访；地图扩展层可以承载 NPC 交互与商店内容。这些基础能够复用，职业、订单、经营和住房功能仍需另行设计实现。

现有装备的奖励主要服务于战斗。例如渔樵套仍提供战斗回血和战斗银两效果。后续可增加钓获、手艺或经营方面的用途，但应另行验证与现有装备效果的兼容，不在本草案中直接替换既有数值。

实现前需检查物品与事件编号、存档兼容及原版经济规则。生活成长应有自己的记录，避免直接借用武功等级和战斗经验，导致普通生活被战斗门槛限制。

## 技术约束与实现方案（2026-10-05 确定）

### 与原版现有机制的关系

- **饥饿已经存在**：公共事件 4“食物饮水”随时间扣食物（变量 15）、饮水（17），不足时不自然回复气血、内力。生活玩法不另加饥饿惩罚，但厨子有天然的客源。
- **钓鱼已经存在**：南郊鱼塘两个钓点（要钓竿、鱼篓，体质差钓不了），杂货店荷西收鲤鱼换女儿红。生活试点从这里扩展。
- **NPC 几乎都能被杀**（204 个有选项的 NPC 中 185 个能战斗），熟客、介绍人都要考虑“他已经死了”。
- **正邪路线**：成了血衣楼主或通缉很重时镇上的人怕你（`WebTown.react`），生活关系要与之兼容。
- **物品没有个体差异**：背包按编号计数，署名、品质只能用不同编号或开关表示。

### 时间：按原版规则

原版只有时间变量 158：在地图上每 200 帧（约 5 秒）加 1，满 3000 长一岁；家里睡觉（喝一瓶女儿红，“能醉上三个月”）加 750。据此：

| 单位 | 时间变量 | 约合现实时间 |
|---|---|---|
| 一年 | 3000 | 4 小时多 |
| 一季 | 750 | 1 小时 |
| 一天 | 3000 ÷ 360 ≈ 8.3 | 40 秒 |

`WebLife.day` 为 14 岁起的第几天，`WebLife.season` 为 0 春 1 夏 2 秋 3 冬。睡一觉正好换一季，鱼按季节出现正好用上。生活活动消耗时间（钓一次过 2 个时辰），时间就是生活玩法的成本——它会让人物变老。

### 存档数据

生活玩法的数据放在 `$game_system` 的实例变量 `@web_life`（一个 Hash），随存档保存，旧存档第一次用时自动建好：

| 键 | 内容 |
|---|---|
| `:v` | 数据版本，以后改格式时据此迁移 |
| `:fish` | 鱼谱：物品编号 => [条数, 最大重量（两）] |
| `:skill` | 熟练度，如 `fishing:` |
| `:clients` | 熟客：`:jose` => { favor:, shown: [...] }，`:cook` => { favor:, done:, served: [...] } |
| `:order` | 当前订单 { client:, item:, qty:, pay:, day: } 或 nil |
| `:flags` | 杂项标记 |

只用 Hash、Array、Integer、Symbol、String，存档导回 PC 原版也能读取。地图事件的出现条件需要开关时另用剧情开关（客栈菜牌用开关 150）。

### 第一个切片（已实现）：钓鱼 → 熟客 → 订单 → 菜牌

- **两处水域**：南郊鱼塘（原版两个钓点改写）、冰火岛渡口（岸边挂着钓线的两处）。十二种鱼（鲤鱼沿用原版），按水域、季节、稀有程度出现。浮子一沉可以“提竿”或“再等等”（更容易上大鱼、稀罕鱼，也可能跑掉）。渔技随钓获增长。

### 防止一直钓鱼的无聊

- **已做**：鱼情。每处水域有鱼情（0～100），钓上一条掉 8～20，每过一天恢复 4，睡一觉（三个月）全恢复；鱼情差时咬钩率最低降到原来的四分之一，并提示“鱼都被你钓怕了，换个地方，或者过些日子再来”。连着钓十来条就该换地方或去做别的事。
- **已有的变化**：季节换鱼、两处水域、“提竿 / 再等等”的取舍、钓上杂物和水贼、订单、鱼谱收集、钓竿各有长处。
- **新水域（已做）**：玉女峰花溪（泥鳅、黄鳝、乌龟、锦鲤；原先误放在商家堡一棵柳树上，已改正）、平安镇西郊篱笆里的小溪（白条、马口鱼、黄颡鱼、娃娃鱼）、大雪山寨的冰溪（只有冬天能凿冰钓：细鳞鱼、哲罗鲑）。共五处水域、二十二种鱼；乌龟、锦鲤可以放生（道德 +3 / +5），哲罗鲑和金鲤一样长内力。鱼谱按水域分页，显示鱼情。
- **钓鱼时的小插曲（已做）**：每一竿有两成几率遇到——下雨（接下来一天咬钩多）、钓线缠住水草（白耗时间）、路人搭话（说一条江湖传闻或当季鱼讯）、野猫讨鱼（分它一条最便宜的鱼，道德 +1）、上游漂下木盆（碎银子）、海鸥成群（海边，这一竿咬钩多）、冰面裂开（冰溪，掉一成气血）、野花开了（花溪夏天，这一竿看得清）。另外钓上来的鱼有 6% 被水鸟叼走。
- **可以再做**：按季节的钓鱼大会（和集会试点合并）；“提竿”改成看准时机按键的小游戏。

### 第三步（已实现）：厨子路线

代码：`src/game/mods/130_厨子.rb`，引擎在 `src/game/web_life.rb` 末尾（菜谱、做菜判定、吃饭增益、做菜画面 Scene_Cook）。

- **入行**：给客栈厨师交满三单鱼后，他教四道家常菜，借出后厨灶台（厨师身边那口锅，地图 20 的 11,7）。厨师原有的“猪肉换祖传宝刀”只在还没和他做生意时提，免得做菜的人带着猪肉总被打断。
- **做菜**：在灶台选菜（缺料的变灰），再选火候（文火 / 武火 / 先武后文）和调味（清淡 / 咸鲜 / 重口）。两样都对出“极品”两份，对一样“好”，都不对“普通”；厨艺越高越常有神来之笔。每道菜的讲究写在提示里。每做一次过两个时辰。
- **十二道菜**：鲫鱼豆腐汤、红烧鲤鱼、红烧肉、鸡汤（厨师入行教）；清蒸鳜鱼、酥油茶煮雪鱼（交过两单菜后厨师再教）；糖醋黄鱼、干煎带鱼、清蒸石斑（荷西教）；麻婆豆腐、孜然烤鱼（独行大侠带回西域香料）；八宝鱼翅（漂流瓶里偶尔夹着御厨的方子）。
- **吃菜的增益**：填饱肚子，并在接下来两三场战斗里带着这道菜的增益（伤害、回血、回内、闪避、减伤、护心、定心等，接装备特效引擎）。同一时间只算最后吃的一道。游戏里一天只有现实 40 秒，所以按场数算而不按天算。
- **销路**：入行后客栈订单约一半是菜，报酬比鱼高；菜牌上会写着你做的菜。
- **熟客独行大侠**（照“一个食摊与一位剑客”）：入了行，他会点一道他想吃的菜，端上去付钱、涨交情，称呼从“店家”到“小兄弟 / 小姑娘”“老弟 / 妹子”；吃了三次后出远门，二十天后回来带西域香料（你学会两道香辣菜），并说明他自己不吃辣——之后他从不点辣菜，开口就是“老规矩，不要辣”；吃了六次后介绍江湖朋友，客栈的菜单报酬再高三成。打狗棒法支线指点棍法时，他照旧先说棍法。
- **厨艺称号**：学徒、帮厨、掌勺、大厨、御厨。

## 分阶段实现与验证

### 首个试点为平安镇集会

复用现有比武招亲内容与镇上商铺，将以下活动组织在同一次集会中。集会是游戏内可主动参与的内容，不采用现实日期的限时活动，也不要求先打赢比武才能参加生活活动。

1. 一项武人能参与的比试，复用既有战斗内容。
2. 一项无需战斗的供货或做饭活动，验证材料、生产与交付。
3. 三位能记住玩家往来的熟客。
4. 一次由熟人介绍开启的新交易。
5. 一处留在地图上的变化，例如玩家的小摊或修好的茶座。

首个试点不同时实现所有职业、完整住房和全部人情分支。先验证活动之间的联系，再扩大内容量。

首批采用三类熟客原型，以下身份与行为均为拟议新增内容：

| NPC 原型 | 经营中的作用 | 用来验证的互动 |
|---|---|---|
| 独行大侠 | 稳定付钱的熟客 | 记住口味、重复消费、介绍朋友 |
| 老叫花 | 偶尔以物换饭的朋友 | 玩家自主施食或交易，回赠物产与见闻 |
| 门派弟子 | 批量采购客户 | 订单数量、产能安排与长期供货 |

### 后续补全生活路线

试点成立后，逐步补齐钓鱼、做菜、客栈收购、固定摊位和一间可布置的小屋。玩家可以卖出普通鱼、留下食材做菜、满足客户需求，再把收入用于工具、配方和居所。

这一阶段形成完整经历：钓鱼供货而认识侠客，侠客介绍远方商人，玩家出门进货并接触门派，赚到钱后回镇置家，熟人又来家中做客。每一步都允许玩家停留、兼做其他事情或选择别的路线。

### 验证标准

首个试点重点检查活动、熟客和地图变化；补全生活路线后再检查完整的居所成长。整体应满足以下体验：

1. 不练武、不战斗，也能完整获得材料、生产、出售并改善居所。
2. 普通经营有可持续的收入，且至少存在两种有意义的材料用途或客户选择。
3. 客户能记住往来，在后续出现不同称呼、订单或回访。
4. 生活奖励直接改善生活，拒绝某项委托不会堵死整条路线。
5. 暂时离开游戏不会造成离线经营惩罚。
6. 同一事件允许不同身份参与，生活活动不以战斗胜利为前提。
7. 至少一次关系进展开启具体的新交易或帮助，至少一处地图变化有实际用途。
8. 拒绝委托、只看热闹或更换生活方向，都能继续获得正常的游戏内容。

首批成立后，再把订单、材料、熟客与经营机制扩展到郎中、裁缝、木匠和行商。复杂商会竞争、完整门派经济和大量专属长剧情留到后续评估。

期望形成的玩家感受是：“我不会打架，但这镇上的侠客大多吃过我的饭，也认得我。”

进一步的自由度目标是：玩家可以决定“这次我想当个爱下棋的厨子，偶尔陪朋友出门”，游戏能持续回应这样的生活选择。
