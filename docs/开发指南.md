# 开发指南

## 1. 整体架构

```
浏览器
 ├─ index.html（static/）        页面外壳：画布、虚拟按键、加载页、对话框、设置面板
 ├─ app.js（src/main.js 打包）
 │   ├─ 下载 ruby.wasm、图片、rxdata、脚本、字体
 │   ├─ 内存文件系统（browser_wasi_shim，文件名不区分大小写，挂载为 /game）
 │   ├─ RGRuntime（src/rgss.js）  Canvas 渲染 / 输入 / WebAudio / localStorage
 │   └─ Ruby VM（ruby.wasm, Ruby 4.0 + 补丁）
 │        ├─ rgss_core.rb    RGSS1 类（Bitmap、Sprite、Window、Tilemap、Graphics、Input、Audio…）
 │        ├─ rgss_kernel.rb  Ruby 1.8 兼容、load_data/save_data、弹窗、Win32API 桩、存档持久化
 │        ├─ rpg.rb          RPG 模块（来自 mkxp-web）
 │        └─ boot.rb         依次 eval game/scripts.json 中的 116 个游戏脚本
 └─ game/
     ├─ scripts.json  构建时从 game-src/scripts 生成（已打补丁）
     ├─ Data/  Graphics/  Audio/  font.woff2  manifest.json
```

### 帧循环
游戏脚本是传统的同步循环（`loop do Graphics.update; Input.update; update; end`）。
`Graphics.update` 先生成本帧的显示列表，再调用 `RGWeb.await_js(:frame, list, fps)` 把控制权交还浏览器（ruby.wasm 的 `evalAsync` 和 JS Promise）。JS 端在下一次 `requestAnimationFrame` 时合成画面，并按 40 帧/秒限速，然后 resolve，Ruby 继续执行。
弹窗（`p`/`print`）和起名输入框也是同样的 await 方式，所以游戏会停在原地等用户操作，和原版行为一致。

### 显示列表
Ruby 端每个显示对象（Viewport/Sprite/Plane/Window/Tilemap）都有 `__record` 方法，返回 JSON 数组片段。`RGWeb.display_list` 把所有可见对象拼成一个 JSON 字符串传给 JS。
记录类型：0 viewport、1 sprite、2 plane、3 window、4 tilemap。具体字段见 `rgss_core.rb` 中各类的 `__record` 和 `rgss.js` 中的 `_drawSprite`、`_drawWindow` 等方法。
位图的像素都保存在 JS 端（每个 Bitmap 对应一个离屏 canvas，用 id 引用），Ruby 只保存 id 和尺寸。

### 渲染规则（与 RMXP/mkxp 一致）
- 图块地图的 z 值 = 32 × (y + 优先级 + 1) − oy；自动元件每 16 帧换一帧，拼接表 `AT_RECTS` 来自 mkxp 的 autotiles.cpp。
- 窗口皮肤分区、光标闪烁、暂停图标和滚动箭头的规则见 `docs/移植笔记.md`。
- 文字：宋体按等宽排版（全角 = 字号，半角 = 字号一半），`text_size` 也按这个规则返回，所以换行和对齐与 PC 版完全一致。其他字体用 Canvas 实际测量。

### 输入
- 键盘映射在 `src/main.js` 的 `KEYMAP` 中（RGSS 按键码：2/4/6/8 方向，11 A，12 B，13 C，17 L，18 R…）。
- 触屏：左侧方向盘按触点角度判断方向，右侧按钮的 `data-code` 就是按键码，多指操作互不影响。
- 按键锁存：按下的键至少保留到下一次 `Input.update`，帧率低时短按也不会丢。

### 存档
`File.open(..., "w")` 打开的文件在 `close` 时调用 JS `persist`，把内存文件系统中的内容以 base64 存到 `localStorage["bjyxts121:<路径>"]`。页面启动时再写回内存文件系统。导出和导入就是直接下载或替换 `Gmud.sav` 文件。

### 内存
不要给 WASI 传 `RUBY_FIBER_MACHINE_STACK_SIZE` / `RUBY_FIBER_VM_STACK_SIZE`。设成 16MB 时，Ruby 会一次预分配约 565MB 的协程栈池，整页内存达到 620MB 以上，手机浏览器（尤其是 iOS Safari）会偶发杀掉页面并自动重新加载，看起来像“播放到一半跳回封面”。使用默认值时整页约 60MB，序幕、建角、地图、菜单、战斗、存档都测试正常。

### Ruby 版本与 ruby.wasm 补丁（重要，升级前必读）
- 使用 `@ruby/4.0-wasm-wasi@2.10.1`（版本已锁定），构建时 `tools/build.py` 会调用 `tools/patch_ruby_wasm.py` 自动打补丁后输出 `public/ruby.wasm`。
- 构建随后还会执行 `tools/pad_wasm_omg.py`：把 30KB～100KB 的 17 个函数体填充到 110KB（填充部分用 `br` 跳过，不执行）。原因是 iOS 26 的 WebKit 对 Asyncify 构建的 wasm 做 OMG 优化编译时内存会冲到数 GiB，网页进程被系统杀掉并自动刷新（WebKit bug 304810）；JavaScriptCore 不会 OMG 编译超过 100KB 的函数，填充后即可避开。代价：这些函数在 iOS 上只用较低一级的 BBQ 编译，略慢；体积增加约 1MB。升级 ruby.wasm 后要重新确认填充数量（脚本会打印）。
- 不能用 3.4：Ruby 3.4.1 的 wasm 版 setjmp/longjmp 每次 `raise`、`break` 跳出块都会泄漏一点 C 栈（上游在 4.0 才修复）。
  游戏每帧都在 Fiber 里 `await`，跑几分钟后栈耗尽 → `SystemStackError` 或 iOS 直接杀页面刷新。这就是“过一会自动刷新回首页”的根因。
- 4.0 的问题：启动时为对象形状表预留 256 MB 内存，iOS 上很容易超限。补丁把这一预分配关掉（改为按需增长），初始化后 wasm 内存约 55 MB。
- 补丁脚本会校验输入文件的 SHA-256 和指令序列，不匹配就报错退出；升级 ruby.wasm 版本时必须重新分析并更新补丁。
- 回归测试：
  - `node tools/stack-drift-test.mjs <栈字节> <次数> <模式>`：each+break / raise / throw 等跳转方式下 C 栈是否漏（模式见脚本头部）。
  - `node --expose-gc tools/wasm-mem-test.mjs public/ruby.wasm`：初始化后的内存。
  - `node --expose-gc tools/ruby-bridge-test.mjs`：20 万次 await 桥接测试。
  - `python3 tools/soak.py 12`：浏览器内循环走动、菜单、换地图、战斗（需先用 smoke.py 生成能进地图的存档 /tmp/rgss_state.json）。
- 缓存：manifest.json 每次向服务器校验；ruby.wasm 与 scripts.json 地址带内容哈希（`?v=`），更新后手机不会继续用旧引擎。

## 2. 常见改动

### 修改游戏内容（剧情、数值、事件逻辑）
1. 直接修改 `game-src/scripts/*.rb`（文件名前三位是执行顺序）。
2. 地图、数据库（`game-src/Data/*.rxdata`）是 RMXP 的 Marshal 格式。可以用 RPG Maker XP 编辑：把 Data、Graphics、Audio 放回一个 RMXP 工程目录，再把脚本导回 Scripts.rxdata；也可以用 Ruby 脚本直接读写（参考 `tools/unpack/stats.rb` 里的类定义桩）。
3. 运行 `python3 tools/build.py --fast`，刷新浏览器即可。
   - `--fast` 跳过音频转码和字体重建，但会检查字体：脚本里出现字体子集没有的汉字时，自动重新生成 `public/game/font.woff2`。
     缺字时浏览器会用系统字体代替，那几个字明显更粗。
   - 重新生成字体需要 `pip install fonttools brotli`，以及字体源 Noto Serif CJK SC（`.ttc`）或 Noto Serif SC（`.otf`，
     可从 https://github.com/notofonts/noto-cjk 的 `Serif/SubsetOTF/SC/` 下载），用环境变量 `CJK_FONT` 指定路径。
4. 按协议要求，在 `docs/改动说明.txt` 里补充记录（格式：脚本名/类名/方法名/行数/用途）。

### 前世奇遇与数值修改器（src/game/web_extras.rb）
- 这是一个普通游戏脚本，构建时以「web:扩展」插在 `117 - Main` 之前，可以访问所有游戏类。
- 调档位、改文案：改 `WebCheat::TIERS`（选项文字、经验、潜能）和 `event_list` 里的对话文字。
  消息窗口一页最多 4 行，每行大约 18 个全角字，超出会自动换行；4 个选项会单独占一页。
- 奇遇用游戏自带的事件解释器播放（`$game_system.map_interpreter.setup(list, 0)`），
  命令码与 RPG Maker XP 一致：101/401 显示文章，102 显示选项，402 选项分支，404 分支结束，355 脚本。
  想加其他奖励（金钱、物品、武功），在 `accept` 里写即可，例如 `$game_party.gain_item(id, n)`。
- 触发条件：开关 1999 关闭且经验低于 `NEW_EXP`。想让老存档也能触发，调大 `NEW_EXP` 即可。
- 修改器：网页端（`src/main.js` 的 `setupSettings`）把指令放进 `rg.cheatQueue`，
  Ruby 端每 5 帧用 `RG.cheatTake()` 取走，处理后用 `RG.cheatReport()` 回传。
  协议很简单：`get`，或 `set|经验|潜能|金钱`；回传 `ok|经验|潜能|金钱|姓名` 或 `err|原因`。
- 改数值后一定要调用 `WebCheat.sync_checks`，存档才能兼容 PC 原版。

### 防作弊检查（已关闭）
原版有两处防作弊，网页版都已关闭，改经验、潜能、金钱等数值不会再被清档：
1. `086 - Scene_Title#save_test`：读档时检查经验/潜能相对游戏时长的增速等，失败会清空存档。由 `tools/build.py` 的 PATCHES 改为直接 `return false`。
2. 公共事件 4「食物饮水」（并行事件）：经验 CRC（变量 152）、潜能校验（变量 153）对不上时清零变量 19-89 并强制存档。由 `src/ruby/rgss_kernel.rb` 的 `RGWeb.patch_common_events` 在载入时把该条件改为 `false`。

相关变量：19 经验、20 潜能、151 金钱 CRC、152 经验 CRC、153 潜能+3、157 年龄、158 年内时间。
如果想恢复原版行为，删掉上面两处补丁即可。

### 给原脚本打兼容补丁
在 `tools/build.py` 的 `PATCHES` 里加一行 `(脚本编号, 原文, 替换, 预期出现次数)`。如果原文找不到或次数不对，构建会报错，防止补丁静默失效。整段替换某个脚本，参考 002 的做法（`WEB_NAME_INPUT`）。

### 加 RGSS 功能或修渲染问题
- Ruby 端接口：`src/ruby/rgss_core.rb`
- 绘制和合成：`src/rgss.js`（`_compose` → `_drawViewport` → `_drawSprite` / `_drawWindow` / `_tilemapItems`）
- 改完运行 `python3 tools/build.py --fast`，它会重新打包 `app.js`。

### 改界面（虚拟按键、加载页、设置面板）
改 `static/index.html` 中的 CSS/HTML 和 `src/main.js` 中的 `layout()`、`setupTouch()`、`setupSettings()`。

## 3. 调试

- 页面上 `window.__vm` 是 Ruby VM，可以在浏览器控制台直接执行游戏里的 Ruby 代码：
  ```js
  __vm.eval('[$game_map.map_id, $game_player.x, $game_player.y].inspect').toString()
  __vm.eval('$game_party.gain_gold(10000)')                  // 加钱
  __vm.eval('$game_temp.battle_troop_id = 1; $game_temp.battle_calling = true')  // 强制开战
  ```
  正式发布前如果不想让玩家改数值，可以删掉 `src/main.js` 里的 `window.__vm = vm;`。
- Ruby 抛出未捕获的异常时，页面会显示“运行出错”和调用栈（格式为 `脚本编号:脚本名:行号`，可以直接对应 `game-src/scripts` 里的文件）。
- 自动测试：先在 `public/` 起服务（`python3 -m http.server 8090`），再运行：
  ```bash
  python3 tools/smoke.py wait:2500 key:Escape wait:1500 key:Enter type:令狐冲 shot:name
  python3 tools/smoke.py --touch --w 844 --h 390 tap:.btn.c tapdir:d shot:mobile
  ```
  步骤：`wait:毫秒`、`key:键名`、`hold:键名:毫秒`、`type:文字`（填起名框）、`tap:CSS选择器`、`tapdir:u/d/l/r`、`shot:名字`（截图到 /tmp/rs_名字.png）、`eval:JS表达式`。localStorage 会保存到 /tmp/rgss_state.json，供下一次测试接着用；删掉这个文件就是全新开始。
  脚本默认使用 `/usr/bin/chromium`，路径不同请修改 `tools/smoke.py`。

## 4. 已知差异与限制

| 项目 | 说明 |
|---|---|
| 联网对战 | 入口改为提示“不支持”，原版依赖 NetworkSupport.dll |
| F12 重置 | 不可用（原版靠 callcc），刷新页面即可 |
| 防修改器检测 | 原版检测金山游侠/Cheat Engine 窗口，浏览器中不生效 |
| 字体 | 思源宋体代替系统宋体，字宽按宋体规则排版 |
